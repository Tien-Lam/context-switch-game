# Terminal workspace UX specification

Updated 2026-10-05 (Australia/Sydney) for release [740c4b5](https://github.com/Tien-Lam/context-switch-game/commit/740c4b59ba06b43a5cdf9fd9216959fe4488a588). This supersedes the September baseline and October 4 tracking reconciliation. Current verification: 107 unit/scenario tests, 50 desktop/mobile Playwright runs, typecheck and production build passed. Two review rounds plus all five specialist charters were exercised; agent-operated browser observations are distinct from human-player research.

## Starting workspace and provider launch

A new run opens Terminal 1 and Terminal 2 as ordinary shells, not auto-started provider tabs. Type `anthill` or `forge` in either tab to launch the corresponding full-window fictional coding-agent CLI. Both are installed from the beginning; launching does not itself assign a ticket or unlock extra execution.

Anthill Code defaults to Ballad and uses a warm conversational composer, permission/plan terminology and context status. OpenMind Forge defaults to Spark and uses a teal compact configuration/status layout with reasoning/workspace terminology. No real products, models, logos or AI connections appear in the game.

## Agent conversation vs Terminal commands

After launch the tab offers Agent and Terminal surfaces with separate drafts, history and suggestions. Agent accepts natural ticket requests such as `please implement APP-101`, using the current provider/model. Do not require shell-perfect syntax for ordinary agent requests. Terminal is where exact command syntax applies.

Both CLIs expose /help, /status, /model, /usage, /permissions, /review and /new. Anthill adds context/cost/diff-oriented interactions; Forge adds /reasoning and /init. Compaction consumes provider quota. Cross-provider model selection is rejected.

Shell game tools include tickets, agents, reviews, upgrades, events, incident, speed and save controls. These are simulated inspection/operation tools, not real connections.

## Virtual workspace

Shared persistent files at /home/dev/delivery; each tab has its own cwd. Seed ticket briefs and fictional source snapshots support exploration. Shell edits do not execute code or fulfil scripted tickets.

Supported command subset:

- Navigation: pwd, ls, cd, tree, find.
- Reading/search/filtering: cat, less, more, grep, rg, head, tail, wc, sort, uniq.
- Mutations: mkdir, rmdir, touch, cp, mv, rm.
- Output/inspection: echo, printf, history, whoami, hostname, date, env, which, help, man, clear.
- Git: simulated inspection (status/log/diff/branch), not real commits or branches.
- Quoted arguments, simple builtin pipelines, > and >> output redirection.

Not a complete POSIX shell: less/more print contents and Git is inspection-only. The current supported syntax, controls and lifecycle are specified in the completion section below; unsupported process/scripting features remain explicitly outside scope.

## Multiplexer progression

- Start: two shell tabs, full-window launched agents, one execution slot.
- One shipped ticket: second execution slot and additional terminal tabs.
- Two shipped tickets: tab naming and authored provider quota-plan event.
- Three shipped tickets: third execution slot, watch agents|reviews|quota|events and pane split.
- pane split <view|tab number>, pane swap and pane close support provider/provider or provider/monitor layouts.
- Dashboard upgrade creates a dedicated graphical operations tab.

The player chooses full-window work or unlocked panes; neither provider is permanently confined to a secondary pane. Background events route to the originating tab.

## Input, layout and pacing

Control/Command+Tab cycles tabs; Alt+1–8 selects a tab; Alt+T opens an extra terminal after unlock. The tab strip scrolls. Preserve visible focus, reduced motion, and usable inputs on narrow/390px layouts. Keyboard history navigation exists; do not confuse that with full shell line-editing compatibility.

Intended passes take roughly 3–16 seconds at 1×; quota starvation/slower choices can extend this. Assignment shows an estimate. Keep work/review/switching actions available rather than rewarding waiting. No attention or human-bandwidth resource.

## Saves and evidence

Terminal UI state persists separately from the version-8 game save; shared filesystem is localStorage version 1. Game JSON export excludes sandbox files. Restart/successful import resets the sandbox.

## Shell and QA completion — 2026-10-05

Delivered shell semantics: &&/; chaining, < input redirection, > and >> output, HOME/PWD/OLDPWD expansion, tilde paths, segment \* / ? globs (including relative parents), cd -, and read-only game-tool pipelines. Quoted/escaped patterns stay literal; no word splitting, arbitrary variables, scripts, substitution, background processes or real shell. Game mutations run directly, not inside chains/pipes.

Tab completes shell commands/paths; Ctrl+C clears unselected input without cancelling scripted work; Ctrl+L clears the current transcript; Shift+Tab retains keyboard navigation. exit, /exit or Ctrl+D on empty input returns to shell; the same provider command resumes the conversation. Background work retains ownership. Use another tab for another provider while this tab owns unfinished work.

Provider banners/status reflect cwd, selected terminal restores after reload, histories work at capacity, optional UI storage failure does not crash play. /help is discoverable from shell help; unlock events follow the owning tab's current surface; revision responses identify their slot. Unsupported sandbox-file requests in Agent offer a plain-language Terminal recovery path.

Save snapshots retain simulated timestamps; optional validated snapshotSequence orders same-clock writes correctly whether DB or emergency storage lags. Legacy version-8 saves remain compatible. Duplicate ticket occupancy and active/completed conflicts reject. Storage reads/clear recover safely, review IDs are stable at fractional boundaries, ending upgrades reject, and risk forecasts account for expected work-context decay.

Mixed-branch contract callbacks no longer blame a repaired branch. Deterministic conservative/reckless/mixed/early-repair routes still reach SHIP-2 with causal endings. Sandbox edits still do not complete tickets; no AI/network runtime was added.

## Final storage fallback audit

Final audit fix [TIE-344](https://github.com/Tien-Lam/context-switch-game/issues/39) keeps valid imports, restart and gameplay operational if browser persistence is unavailable. Either save backend can succeed; when neither can write, an explicit not-saved warning advises exporting before close/reload. Background saves do not reject unhandled, UI/workspace resets finish, and stale snapshot failures cannot overwrite a newer save's status. Five additional unit regressions and a dual-denied-storage scenario on desktop/mobile pass; 107 unit/scenario tests and 50 browser runs (25 scenarios × two Chromium configurations). Earlier live-campaign and keyboard evidence retains its own build attribution in the [QA report](https://github.com/Tien-Lam/context-switch-game/blob/main/docs/linear-migration/documents/fb98360a-fb99-4de8-82bc-126a81544525.md).

[TIE-345](https://github.com/Tien-Lam/context-switch-game/issues/40) prevents restored event announcements from replaying when hydration finishes. The event cursor is seeded only after the saved run loads; new live events still route normally. Offline catch-up progress remains inspectable via reviews/events and the catch-up notice rather than replaying saved transcript alerts. A desktop/mobile reload regression retains exactly one fresh shipment announcement.
