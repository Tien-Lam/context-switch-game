# Evidence based gameplay evaluation and agent pickup protocol

<!-- linear-source:0869e667-617c-4ae4-a09b-2d06abbea007 -->

Migrated from Linear on 8 October 2026. This preserves the original specification and dated history; historical workflow instructions and earlier pending statuses describe their original context. Current work is tracked in [GitHub Issues](https://github.com/Tien-Lam/context-switch-game/issues) and [Projects](https://github.com/users/Tien-Lam/projects/2).

This project evaluates the shipped decision-depth baseline and prepares bounded improvements for agent pickup. Gameplay implementation is queued, not started, following the user's latest instruction. Correctness, structural depth and taste judgments remain separate; agents do not establish human population enjoyment.

## Product taste brief

Fast CLI-first orchestration, minimal passive waiting, terminal syntax outside conversational agents, mechanically useful provider habits, understandable review evidence, quick interesting recovery and upgrades that unlock capabilities. No attention, stamina or human bandwidth meter. The existing user feedback grounds these preferences; it is not a validated population model.

## Evaluation workflow

Independent browser players use a declared objective and no source or solution route before first play. Expert systems auditors may inspect rules but must disclose their prior context. Record exact commands, visible evidence, predictions and outcomes, discovery, repetition and stopping points. Keep simulated wait separate from browser latency.

For candidate validation, use neutral labels, matched starting states and routes, critics who did not implement the change, both presentation orders, and ties or insufficient evidence. Compare experiences, not builder intentions. Feature ablations and deliberately degraded controls test whether evaluators notice consequential play rather than verbosity or novelty alone. Candidate A/B validation remains a future acceptance gate: this preparation pass evaluates the unchanged baseline.

## Repository artifacts

`.agents/playtesters/protocol.md` is the shared protocol. The five specialist charters retain their distinct responsibilities and now require evidence and comparative judgments. Reports live in `.agents/playtesters/reports/`. Charters are saved files; agents are sessions created when invoked, not permanent processes.

Two existing expert sessions perform systems and narrative audits; they are not fresh-context personas. New session creation hit the task-thread limit. The narrative expert's browser was unavailable and its source/engine findings are not described as browser play.

The primary browser route shipped APP-101, knowingly unsafe APP-118, safely bypassed PERF-204, repaired FIX-118 and revised/shipped PLAT-77. It used 22 typed commands and three in-game tab switches. No candidate build or blind preference win is claimed.

## Agent ticket requirements

Each improvement ticket must contain confirmed evidence or an explicitly labelled hypothesis, exact reproduction, player impact, bounded implementation proposal, owned file areas, non-goals, deterministic tests, rendered-browser acceptance, dependencies and review requirements. Ready tickets have no unresolved product choice. Experimental tickets specify a falsifiable result and permit rejection rather than automatically shipping extra complexity. Use mise and Bun; preserve save compatibility; keep authored data in src/content and deterministic rules in src/game; no real provider names, AI APIs or telemetry services. Run `mise exec -- bun run check` and affected browser tests before completion.

## Research basis

[Procedural personas](https://www.antoniosliapis.com/papers/automated_playtesting_with_procedural_personas_through_mcts_with_evolved_heuristics.pdf) supports objective-driven play styles. [LLM judge research](https://arxiv.org/abs/2306.05685) identifies position, verbosity and self-enhancement biases in conversation evaluation, not validated game-fun accuracy. [Moderate divergence](https://scholars.ln.edu.hk/en/publications/fun-as-moderate-divergence-evaluating-experience-driven-pcg-via-r/) motivates a learnable variation hypothesis, not a universal metric. [AI engagement prediction](https://arxiv.org/abs/2107.12061) depends on calibration to human data. [Grounded profiles](https://arxiv.org/abs/2411.10109) and [human-surrogate limitations](https://arxiv.org/abs/2410.19599) support grounding judgments in actual preferences and labelling uncertainty.
