# Game design specification

Updated 2026-10-05 (Australia/Sydney) for release [740c4b5](https://github.com/Tien-Lam/context-switch-game/commit/740c4b59ba06b43a5cdf9fd9216959fe4488a588). This supersedes the September baseline and October 4 tracking reconciliation. Current verification: 107 unit/scenario tests, 50 desktop/mobile Playwright runs, typecheck and production build passed. Two review rounds plus all five specialist charters were exercised; agent-operated browser observations are distinct from human-player research.

## Fictional providers and models

Anthill Code (`anthill`) is conversational, warm-toned and context/plan oriented. Couplet is quick/frugal; Ballad is the default balanced model; Epic is deep/high-cost and unlocks at 44 peak trust.

OpenMind Forge (`forge`) is a compact task/workspace-oriented CLI with a reasoning dial. Spark starts available; balanced Forge unlocks at 36 peak trust and deep Foundry at 54. Low/medium/high reasoning changes setup quota and review risk. Models belong to their provider; a tab cannot silently run the other provider's model.

All player-facing names and branding remain fictional. Familiar CLI interaction patterns are inspiration, not real integrations.

## Actions and state

Launch an agent from a shell; choose model/permission/reasoning; request work naturally with a ticket key; inspect tickets and reviews; plan before coding; compact active context; switch providers; approve/revise/escalate; mitigate incidents and buy unlocked upgrades.

The actual engine state is `idle → working → awaiting-review`, with `quota-paused` during insufficient capacity. Revision returns to working; approval/escalation frees the slot. Planning is a quota-spending setup choice, not a separate timed state. There is no general player pause/resume action.

## Economy and unlocks

Quota, execution slots, context, trust, repository health and debt drive decisions. No attention resource.

- Start: two shell tabs, both providers installed, one execution slot.
- One shipment: second execution slot and additional terminal tabs.
- Two shipments: tab naming and an authored Anthill quota-plan change.
- Three shipments: third execution slot, live monitors and split panes.
- Dashboard: optional purchased upgrade, never required to play the CLI loop.

Upgrades: repository playbook, fast checks, context notes, live terminal dashboard, workspace isolation, pre-demo observability, quota plan, and the second-chapter CI integrity guard. Upgrade eligibility and effects are authored in `src/content/upgrades.ts`; observability specifically affects the freshness audit rather than every incident.

## Review decision rule

Show summary, files, diff scope, test evidence, warning, risk-source breakdown, risk estimate and explicit PASS/BLOCKED gate. Authored green tests do not override a high aggregate risk or unresolved warning.

Approve immediately accepts the risk and may create a deterministic defect. Revise consumes another agent pass and narrows the change. Escalate takes a safe resolution but spends trust and forfeits reward. Tests are displayed evidence, not a separate generic run-tests game action. Keep review rationale understandable without source-code expertise.

## Authored campaign

Chapter one: APP-101 banner, APP-118 privacy toggle, PERF-204 cache, PLAT-77 runtime, API-88 webhook, DATA-312 parallel reports, UI-229 quota display, OPS-41 freshness audit and SHIP-1 investor demo.

Chapter two: QA-401 green build, API-420 account API, UI-421 account panel, INT-422 contract join, UI-502 retry, API-503 gateway rollout and SHIP-2 release.

Conditional repairs: FIX-118, FIX-204, FIX-77, FIX-312, FIX-401, FIX-420 and FIX-502. Earlier approvals determine later callbacks. Repairs resolve the relevant causal defect; clean runs do not receive those tickets. The gateway incident distinguishes scaling capacity from stopping the request loop through rate limiting or rollback before repair.

## Pacing and ending

Intended work passes are roughly 3–16 seconds at normal speed; player decisions and parallel throughput, not idle waiting, are the focus. Revision returns within seconds. Throughput includes total shift time, so idle time has a throughput cost. A short policy-specific quota wait can nevertheless avoid a revision and improve that route's total score; testing has not established waiting as a generally dominant strategy.

The ending separates throughput, reliability, trust and debt, explains the calculation and recounts decisions across both chapters. Overall session duration and human-player enjoyment remain unvalidated.

Follow-ups are delivered in [TIE-331](https://github.com/Tien-Lam/context-switch-game/issues/29)–[TIE-333](https://github.com/Tien-Lam/context-switch-game/issues/31) and confirmed QA fixes [TIE-336](https://github.com/Tien-Lam/context-switch-game/issues/32)–[TIE-342](https://github.com/Tien-Lam/context-switch-game/issues/38). At the user's request, [TIE-333](https://github.com/Tien-Lam/context-switch-game/issues/31) uses an actual agent-operated browser playtest rather than human participants. Human-player enjoyment and audience-wide session duration remain unvalidated and are not requirements of this completed engineering/agent-QA scope.

## Shell and QA completion — 2026-10-05

Delivered shell semantics: &&/; chaining, < input redirection, > and >> output, HOME/PWD/OLDPWD expansion, tilde paths, segment \* / ? globs (including relative parents), cd -, and read-only game-tool pipelines. Quoted/escaped patterns stay literal; no word splitting, arbitrary variables, scripts, substitution, background processes or real shell. Game mutations run directly, not inside chains/pipes.

Tab completes shell commands/paths; Ctrl+C clears unselected input without cancelling scripted work; Ctrl+L clears the current transcript; Shift+Tab retains keyboard navigation. exit, /exit or Ctrl+D on empty input returns to shell; the same provider command resumes the conversation. Background work retains ownership. Use another tab for another provider while this tab owns unfinished work.

Provider banners/status reflect cwd, selected terminal restores after reload, histories work at capacity, optional UI storage failure does not crash play. /help is discoverable from shell help; unlock events follow the owning tab's current surface; revision responses identify their slot. Unsupported sandbox-file requests in Agent offer a plain-language Terminal recovery path.

Save snapshots retain simulated timestamps; optional validated snapshotSequence orders same-clock writes correctly whether DB or emergency storage lags. Legacy version-8 saves remain compatible. Duplicate ticket occupancy and active/completed conflicts reject. Storage reads/clear recover safely, review IDs are stable at fractional boundaries, ending upgrades reject, and risk forecasts account for expected work-context decay.

Mixed-branch contract callbacks no longer blame a repaired branch. Deterministic conservative/reckless/mixed/early-repair routes still reach SHIP-2 with causal endings. Sandbox edits still do not complete tickets; no AI/network runtime was added.

## Final storage fallback audit

Final audit fix [TIE-344](https://github.com/Tien-Lam/context-switch-game/issues/39) keeps valid imports, restart and gameplay operational if browser persistence is unavailable. Either save backend can succeed; when neither can write, an explicit not-saved warning advises exporting before close/reload. Background saves do not reject unhandled, UI/workspace resets finish, and stale snapshot failures cannot overwrite a newer save's status. Five additional unit regressions and a dual-denied-storage scenario on desktop/mobile pass; 107 unit/scenario tests and 50 browser runs (25 scenarios × two Chromium configurations). Earlier live-campaign and keyboard evidence retains its own build attribution in the [QA report](https://github.com/Tien-Lam/context-switch-game/blob/main/docs/linear-migration/documents/fb98360a-fb99-4de8-82bc-126a81544525.md).

[TIE-345](https://github.com/Tien-Lam/context-switch-game/issues/40) prevents restored event announcements from replaying when hydration finishes. The event cursor is seeded only after the saved run loads; new live events still route normally. Offline catch-up progress remains inspectable via reviews/events and the catch-up notice rather than replaying saved transcript alerts. A desktop/mobile reload regression retains exactly one fresh shipment announcement.
